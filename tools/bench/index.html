How to read these results

Speed and file size

Above 1× means ptpng is faster than the reference measured in the same run. The dashed line marks equal speed. File size is a separate comparison: 167.6% of reference bytes means a 67.6% larger PNG file.

PNG compression is lossless; dimensions and decoded pixels stay identical. Changing the reference changes the comparison, not ptpng's compression settings. zlib and zlib-ng can produce different file sizes at the same numbered level.

Machines can change

Hosted runners are fresh virtual machines. Compare the recorded CPU and runner image before interpreting a change. These ratios do not replace alternating old/new measurements on one machine.

Timing and fixtures

Decoder timings use medians of 12 alternating rounds after warm-up from commit e6f083c onward; earlier runs used best-of-12. Encoding uses five rotated rounds. Allocations and checksums are included; file I/O and freeing returned output are excluded.

From 1 October 2026, the encoder targets level-6 file sizes with full-row filtering and dynamic Huffman blocks. Earlier points use the previous speed-first compressor; compare time and size together.

Fixtures contain generated photo-like gradients, graphics and random noise. PNG streams can differ between OSes. Palette inputs expand to RGBA8 for both encoders.

Memory is a reference

Warm-buffer copying measures payload MB/s over a 128 MiB working set. It is not a theoretical PNG limit: decoding reads compressed bytes and also reconstructs pixels and verifies checksums.
